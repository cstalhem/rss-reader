# Frontend forms use plain controlled state + shadcn Field primitives — no form library

Researched during #97 (feeds & folders UI) against the then-current shadcn docs: shadcn retired its RHF-coupled `<Form>` wrapper in favor of the library-agnostic `Field` component family, and documents React Hook Form, TanStack Form, and Formisch as equal peers. For this app's forms — a handful of 1–3 input dialogs whose one real validation rule ("is this a URL?", "is the name non-empty?") is enforced server-side anyway — either library adds dependencies, a render-prop or `Controller` DSL, and roughly 1.5–2× the lines per field while its actual payoff (schema reuse, field arrays, async/cross-field validation, eager-validation modes) goes unexercised. TanStack Form's apparent synergy with TanStack Query is brand affinity, not integration — the "integration" is `await mutation.mutateAsync(value)` in a submit handler, identical under any approach. Radix-based controls also nullify RHF's signature uncontrolled-performance benefit: every shadcn Select/Switch/Checkbox needs a `Controller` regardless. So: plain controlled `useState`, shadcn `Field`/`FieldLabel`/`FieldDescription` for markup and a11y, browser constraint validation (`type="url"`, `required`), and server-side errors through the centralized MutationCache toast.

## Consequences

- Revisit when a form with genuine state complexity lands — multi-field dependencies, async validation, or field arrays (candidates: a future scoring-settings surface, category batch-edit if it outgrows checkboxes). Adopt for that form only; don't migrate the small dialogs.
- Migration stays cheap by design: the `Field` markup is identical under RHF (`Controller` render prop) and TanStack Form (`form.Field` render prop) — a library drops in around the existing JSX without restructuring it.
- Overlay forms mount fresh per open (state initializers capture the target entity), so there is no reset/synchronization logic a form library would otherwise own — keep that invariant if a library is ever introduced.
